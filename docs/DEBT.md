## Tier 1 — Segurança de plataforma (pendências pós-entrega)

| # | Item | Severidade | Rationale | Caminho para resolver |
|---|---|---|---|---|
| T1-3 | **No mTLS entre serviços internos** | 🟡 Média | `INTERNAL_API_TOKEN` protege, mas tráfego entre gateway↔orchestrator↔agents via HTTP plain na VPC. | AWS VPC endpoints + security groups restringem tráfego; mTLS seria overkill mas ideal. |
| T1-8 | **Upload SAS de documentos/foto sem limite de tamanho nem content-type** (ADR-066/082) | 🟢 Baixa | A SAS do Azure Blob (ADR-082) não impõe tamanho **nem** Content-Type do PUT (o presign do S3 ao menos assinava o content-type) → médico autenticado pode subir arquivo arbitrariamente grande/de outro tipo no próprio prefixo (abuso de storage/custo; escopo do próprio tenant, ator identificado; allowlist de MIME segue validada no pedido da URL). | Validar tamanho/content-type reais pós-upload (GetProperties antes de registrar) + quota; lifecycle nos containers já limita acúmulo. |
| T1-10 | **Embeddings/RAG ainda no Bedrock (última dependência AWS de runtime)** (ADR-028/082) | 🟢 Baixa | Após o ADR-082 (arquivos → Blob, STT → Azure Speech), o único serviço AWS restante no código de runtime é o embedding Cohere via Bedrock sa-east-1. No portfólio Azure roda com `EMBEDDINGS_ENABLED=false` (RAG desligado). | Migrar p/ um provedor de embedding fora da AWS (ex.: Azure OpenAI/Cohere API) — muda dimensão do vetor ⇒ exige nova coluna/reindex do pgvector (migration + reindex total). Só com novo ADR. |
| T1-9 | **`CHECKUP_DATABASE_URL` morto nos containers clínicos, com creds master** | 🟡 Média | Auditoria de roles 2026-06-24 (pós-incidente 28P01 [[incident-gateway-db-auth-28P01]]): os 5 containers do box clínico (gateway, web, notifier, orchestrator, agents) recebem `CHECKUP_DATABASE_URL` via `.env`/compose, mas **nenhum código clínico o lê** (grep: só `apps/checkup/src/lib/db` + ASG/compose do checkup o consomem). É config morta no box clínico (checkup roda em ASG próprio, ADR-045, com seu DSN via SSM `checkup_app`). Pior: os containers em runtime carregam o valor **velho com role `cerebroadmin` (master)** — master creds em repouso no env de 5 serviços que não tocam o schema `checkup` = blast-radius full-RDS se um container vazar. O `.env` (mtime 12:05Z) **já** foi corrigido p/ `checkup_app`; o master só sai dos containers no próximo recreate. | (1) Remover `CHECKUP_DATABASE_URL` do `.env`/compose **dos serviços clínicos** (mantê-lo só no path do checkup). (2) Garantir que o DSN do checkup nunca use `cerebroadmin` (least-privilege: `checkup_app` basta; master só p/ DDL/migration de schema, e aí num path dedicado, não no env de runtime). (3) `--force-recreate` p/ purgar o master dos containers vivos (ou deixar o próximo deploy fazer). |
